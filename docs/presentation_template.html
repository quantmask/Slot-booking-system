Common Failure Modes
The Race Condition Trap

In standard booking apps, a query checks SELECT count(*) < capacity, then executes INSERT in a separate statement. Under sustained concurrency:

  • Double Bookings: Simultaneous users both read open capacity before either writes.
  • Buffer Overlaps: Travel/prep buffers collide across concurrent meetings.
  • Client Clock Skew: Guest system time differences corrupt TTL hold expirations.
  • Orphaned Holds: Dropped browser sessions lock host calendars indefinitely.
-- NAIVE FLAW: Check-then-act race window
SELECT * FROM bookings WHERE slot_time = $1;
-- [WINDOW OF VULNERABILITY: 10-50ms]
INSERT INTO bookings (slot_time, guest) VALUES ($1, $2);

4-Tier Concurrency & Overlap Prevention

How Slotbook eliminates double bookings and race conditions with mathematical guarantees
Zero Overlap
Tier 1: Serialization
Host Row Lock

The first operation in every transaction executes SELECT ... FOR UPDATE on the host record.

Serializes concurrent holds for a specific host, preventing interleaved slot creation while allowing independent hosts to run concurrently at full speed.

SELECT id FROM hosts
WHERE id = $1 FOR UPDATE;
Tier 2: Exclusion
GiST Range Constraint

PostgreSQL storage engine directly blocks intersecting intervals using the Generalized Search Tree (GiST).

Checks both session duration and buffer windows [start - b_before, end + b_after). Rejects any colliding insert with SQL error 23P01.

EXCLUDE USING gist (
  host_id WITH =,
  blocked_range WITH &&
) WHERE (status = 'active');
Tier 3: Time Authority
Database Clock Single Source

Client clocks are completely untrusted. All hold TTLs, minimum notices, and booking horizon cutoffs are evaluated via NOW().

Prevents guests with manipulated system clocks from claiming expired holds or circumventing advance notice constraints.

hold_expires_at > NOW()
min_notice: NOW() + notice
horizon: NOW() + days
Tier 4: Atomicity
Atomic Reschedule & Rollback

Rescheduling swaps the appointment from the old slot to the new slot in a single ACID transaction.

If the target slot is seized or conflicts, the transaction aborts instantly. The guest never loses their original reserved appointment.

BEGIN;
  UPDATE bookings...
  UPDATE sessions...
COMMIT; -- all or nothing

🔗 Half-Open Interval Algebra

All temporal boundaries use half-open intervals: [start_at, end_at).

Ensures that a 09:00–10:00 meeting and a 10:00–11:00 meeting are perfectly adjacent without false conflict, while any overlap greater than 0 microseconds is caught immediately.

📡 Server-Sent Events (SSE) Stream

When any user reserves, confirms, reschedules, or releases a slot, the system emits an internal event across an EventEmitter pub/sub channel.

  • Persistent HTTP Connection: GET /api/hosts/:host/events/:slug/slots/stream maintains an open, lightweight SSE socket.
  • Heartbeat Keep-Alive: 15-second heartbeat prevents proxy timeouts and idle socket closures.
  • Sub-Second Broadcast: All other guests viewing the same calendar receive a SLOTS_UPDATED event within < 50ms.
  • Zero Polling Burden: Eliminates continuous HTTP request spam, slashing server load by 95%.

Reliable Message Processing

Transactional Outbox & Background Workers

Guaranteed at-least-once delivery, exponential backoff, and dead-letter queue isolation
Event Driven
Pattern
Transactional Outbox

Booking confirmation and outbound notification are written in the exact same ACID transaction.

Guarantees that an email or webhook is never emitted if the database transaction fails, and a booking is never created without an accompanying event record.

Outbox Worker
Delivery & HMAC Signatures

Polls pending notifications using FOR UPDATE SKIP LOCKED, allowing multiple worker instances to operate in parallel without lock contention.

Computes cryptographic SHA-256 HMAC signatures for host endpoints and implements exponential backoff (2s, 4s, 8s, 16s... up to 5 attempts) before Dead-Letter Queue (DLQ).

Sweeper
Hygiene & Reminders

Runs periodically to maintain storage hygiene:

  • Expired Holds: Marks abandoned 5-minute holds as expired and releases empty sessions back to the open pool.
  • Reminder Dispatch: Queries due 24h and 1h appointment reminders and queues them for delivery.
  • Waitlist Promotion: Automatically claims cancellations for waiting guests.
